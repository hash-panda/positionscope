# 应用内更新

0.2.3 开始支持「设置 → 关于与更新 → 检查更新 → 下载 → 重启更新」。此前版本只能打开发布页，需要手动安装一次 0.2.3。此后只在主动点击时访问官方 GitHub 稳定版本，不轮询、不在后台调用模型。

## 状态与安装

- 检查版本不下载；下载仅响应用户点击。一个主进程协调两个窗口，关闭设置页后保留进度。
- 下载完成且系统检查成功才出现「重启更新」。macOS Squirrel 原生行为也会在下次退出时安装已准备好的更新，界面明确说明。
- 开发模式、磁盘映像与 App Translocation 路径不启用安装。请先将应用移入“应用程序”。
- 更新失败显示固定、无敏感响应的错误，保留当前安装；重新检查后可重试下载。网络使用独立、非持久化 Electron 会话及系统网络代理，没有账户/持仓/模型参数、Cookie 或 API Key。

## 信任与边界

只认 `hash-panda/positionscope` 完整的数字稳定版、当前架构和固定资产命名；要求 GitHub SHA256 元数据、发布验证记录中的版本/架构/应用身份、签名/装订/Gatekeeper 结果、最低 macOS 版本与 ZIP 摘要一致。下载以流写入随机临时目录，限制大小和时间；中断、长度不符、摘要不符删除临时包。

经摘要验证的 ZIP 通过只绑定 127.0.0.1 的临时随机口令路径交给 Electron 内置 Squirrel.Mac，由系统校验应用签名并替换/重启。服务器只接收 GET，检查 Host、拒绝 Origin，仅服务两条固定路径；渲染器不能传 URL 或文件路径。ATS 只开启本地网络例外，没有关闭外部 TLS 检查。安装动作只接受本应用顶层窗口 IPC。

发布验证记录不是独立的供应链签名；GitHub 仓库及 Apple 发布身份仍是信任根。实际下载在本机重新计算摘要，原生更新器验证签名。没有自写 shell 覆盖应用，也没有未签名安装后备路径。

## 验证

- Node：稳定版/架构/摘要边界、负面下载、重定向和大小限制、同一时刻单任务、只在原生 ready 后安装、重复重启、IPC 来源，以及 loopback 路径/Host/Origin 检查。
- UI：检查/下载/进度/验证/准备状态、导航后状态保留、重启 IPC、无需打开 GitHub。
- 签名流程：`scripts/verify-native-updater.py` 使用独立测试应用身份、临时 profile 和测试入口复制两份本次签名应用；在 Mac 上演练 0.0.1 → 0.0.2、替换包和重启读回版本。复用真实 UpdateInstaller/摘要校验/loopback/Squirrel，但公开发布元数据是合成夹具，测试副本不会分发或声称已经公证。
- 双架构演练失败会阻止正式发布。生产包仍必须完成既有签名、公证、装订和 Gatekeeper 验证。
- 此项验证不能替代用户 Mac 的权限弹窗、真实配置/模型/账户验收。

官方来源（2026-11-07 核对）：[Electron autoUpdater](https://www.electronjs.org/docs/latest/api/auto-updater)、[Squirrel.Mac](https://github.com/Squirrel/Squirrel.Mac)。
