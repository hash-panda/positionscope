# PositionScope 产品与运营规范

起点：2026-10-24。负责人为项目维护者，自动任务承担有证据的评审、有限范围实现和报告。目标是验证持续使用与付费理由，再扩大推广。没有增长或收益保证。

## 迭代与发布

每日读取默认分支、CI、Issue、上一报告和真实版本状态，按 [100分标准](product-quality.md) 检查。每个分项用通过/失败/未验证，不用没有依据的总分。候选按用户影响、证据强度、工作量及风险排序；先修数据/凭证/安装，再做视觉扩展。已有Issue去重，一个可验收范围一个PR，写触发→前后行为→测试→限制。检查通过且无未解决问题才合并；有二进制变化才升版本。签名/公证失败不发布，不退回未签名发布。官网能力与实际Release同步。

## 阶段目标与停止条件（目标，不是预测）

| 周期 | 主要工作 | 决策证据 |
| --- | --- | --- |
| 第1周 | 完成签名输入、Mac安装回归、安全存储方案，招募5位符合场景的自愿测试者 | 至少3人成功完成只读接入；记录失败原因；不足则优先修上手，不扩大宣发 |

## 指标定义与初始状态

初始公开数据见 docs/ops/metrics/2026-10-24.json。Stars/Forks是可见度；Release下载次数是请求次数，不是人数。网站访问、激活、留存、客户、收入目前未知，不填0假装测过。当前无遥测、支付或增长统计后端。

激活：一位自愿测试者在自己的Mac完成只读接入且核对至少一份快照。W1留存：激活后第7–13天至少一次实际使用，经用户自愿反馈确认；无反馈归未知，不能自动记流失。价值指标：识别一次真实变化所需时间、错误/漏报数、用户是否因解释而更快复核；不以投资收益归因。将来若加入分析，先明确数据最小化、告知/选择、保留期、删除方式；不收交易Key、持仓或金额作为营销数据。

每周报告：本周上线与CI链接、实际指标/来源/分母、用户反馈、一个有效/无效实验、下周3项、阻塞。每月第一份周报增加渠道成本/激活/留存/收入/支持工时和是否继续。每年第一份周报增加年度复盘；首个完整年度在2027-10-24后复盘。完整数据不存在就明确缺失。公开报告不能含个人财务或账号资料。

## 商业验证与全成本

优先开源核心+可选Pro（历史复盘、规则告警、导出）作为待验证假设。基础只读监控不因收费扩大交易权限。先访谈、可点击功能说明及明确价格的意向反馈，不虚构购买入口。候选报价 ¥29/月、¥199/年仅作访谈测试，尚未收费/接受预售。现有MIT授权需尊重，不能撤销既有授权；Pro范围与依赖授权单独核对。

示例（全部是假设）：20位月付×¥29=¥580收入，支付费按3%=¥17.4、服务成本¥100、退款准备5%=¥29，则现金贡献¥433.6，未计税与人力。若维护8小时×¥100/小时，经济利润为-¥366.4。更高用户量同样要计支持、退款、获客、模型、托管、合规及税务实际成本。BYOK降低模型代付成本但增加用户接入阻力；托管AI要先有预算、计量和上限。没有确认预算前不购买服务或投广告。
