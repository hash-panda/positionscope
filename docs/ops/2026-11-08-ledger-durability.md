# 2026-11-08：研究账本持久化耐久性收口

## 结论与范围

本轮从已发布 v0.2.8、开放 #3/#7/#23 和当日既有报告继续去重。研究账本已使用0600临时文件和原子重命名，但此前通过 `writeFile` 后直接重命名，没有像加密配置与模拟账本一样在提交前刷新文件内容。原子重命名避免读到半个文件，不等于断电前数据已经进入稳定存储，因此“原子保存”的耐久性证据不完整。

改进后，研究账本按“独占创建0600临时文件 → 写入 → `fsync` → 关闭 → 原子重命名”的顺序提交。新增合成文件系统顺序回归，确认 `sync` 发生在关闭和重命名之前；既有保存失败回滚、原文件保留、并发串行、损坏文件失败关闭继续保留。没有读取真实账户、模型输出或用户账本，没有改变筛选、提醒、影子观察、风险公式、模拟成交或任何交易权限。

## 官方资料与取舍

- Binance USDⓈ-M 用户数据流仍需60分钟保活生命周期；它可提升实时性，但必须先验证重连、乱序和断档。本轮不替换稳定REST。
- Bybit仓位流会在订单创建/修改/取消时产生消息，即使仓位没有实际变化，继续支持“事件不等于成交或资金流”的既有口径；当前产品保持Binance-only。
- DeepSeek 2026-10-17开放Search/Fetch并更新 `deepseek-flash` alias，Responses API提供JSON Schema；外部搜索费用、来源治理和真实模型质量仍未验证，本轮不接入。
- 未发现要求本轮修改同类菜单栏/组合工具架构或恢复OKX/Bybit适配的实质变化。

最小后续验证仍是：获准的只读测试账户并行REST/用户流对照；用户Mac签名包钥匙串、原生菜单和更新重启；获准真实模型的结构化输出、费用与失败率；至少七天、三十笔成对模拟样本。没有这些证据，不声称实时性、模型盈利能力或用户增长已经验证。
