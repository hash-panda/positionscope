## 本轮最小实验

复用[#93](https://github.com/hash-panda/positionscope/issues/93)，完成“部分成交数量对应单次资金费”独立合成实验，新增`partial-funding-experiment.ts`。这是生产接线前的局部算法验证，不是已修复生产部分成交或已具备完整模拟结算。

预先固定假设：只对结算前已成交数量按结算markPrice与rate估算；未成交/已撤销余量不计费；多空与费率正负决定收付；同毫秒无法确定成交与结算先后时弃权，不猜测。保持现有全成生产账本和历史事件不变，未通过则不接线、不发布。

| 合成输入 | 固定期望 |
| --- | --- |
| 2000ms成交1，4000ms再成交0.5；3000ms结算，mark100/rate0.001 | 多头-0.1，空头+0.1；计费数量1 |
| 同一成交输入，5000ms结算 | 多头-0.15；计费数量1.5 |
| 费率-0.001，3000ms结算 | 多头+0.1，空头-0.1 |
| 4000ms同毫秒成交/结算 | 数量和资金费未知，status=ambiguous-at-settlement |
| 2个币原单仅成交1，之后撤销余量1 | 只按已成交1计费；已成交持仓不因撤单消失 |
| 重复同成交ID、等值数量 | 不重复计算；相同ID不同数量/时间拒绝 |

已实际验证以上矩阵、JSON恢复/输入不变、未来结算/未来成交/错标的/错来源/无效金额拒绝。12位定点只在最后做一次除法；不足最小单位的支出向不利方向取整、收入向零取整，是实验保守精度规则，不是交易所账单精度声明。本次新增3项Node回归，完整248 Node、25 Python、类型/生产构建、七页官网源码/清单、diff检查通过。UI未改，现有UI/axe与Mac以本PR实际CI审查为准，不预填。

算法只接收一条具备source字段的结算记录和开仓成交列表；不读取网络，不证明source字符串对应的真实来源，不判断区间覆盖完整性，不累加账户账本。未支持部分平仓、数量净额路径、保证金、生产预算占用、磁盘崩溃恢复或完整资金费窗口。未将成交报价时间当交易所实际成交确认。下一步先验证部分平仓/预算协议，再接生产事件；不继续无边界扩充独立引擎。
