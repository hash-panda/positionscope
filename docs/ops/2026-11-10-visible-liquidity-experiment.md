## 本次可验证改进

新增一个未接入生产决策的纯 TypeScript 撮合原语：对一张冻结的 Binance USDT 永续公开深度快照，按订单顺序消费私有深度副本。前序订单消耗的档位不会被后序订单重复使用；深度不足时分别返回 `partial` 与 `unfilled`，同时保留请求量、成交量、剩余量、加权价格、显式滑点名义金额和手续费。重复订单 ID、非法数量步进和成本参数均关闭失败，输入盘口保持不变。

这是 #93 的最小合成实验，不是生产成交生命周期。它没有持久化跨事件剩余深度，不知道真实队列位置，也未把部分成交写入现有 `paper-ledger-v1`。因此它只证明“单次冻结快照内不重复消费”的确定性算法可测，不能证明真实可成交、模拟净收益或盈利优势。

本地实际验证：229/229 Node、25/25 Python、主进程/预加载 TypeScript、Vue typecheck 与 Vite production build 通过。新增三项覆盖买侧顺序消费与部分/未成交、卖侧费用/确定性、重复 ID/非法步进/非法成本关闭失败。CI、UI/axe 和 Mac 合成检查以 PR 精确 head 为准；本轮无 UI 变更。
