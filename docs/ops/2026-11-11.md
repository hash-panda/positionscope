## 选题、实验与结果

复用 #93。执行改进的假设为：模拟账本一旦进入重命名后的不确定提交阶段，阻止后续写入并要求重开校验，应保住磁盘事件和内存状态，避免排队写入覆盖历史。验收使用同一组合成事件、相同文件系统替身，分别注入目录 sync 与 close 故障，检查磁盘字节、内存、排队写入、重开和相同 ID 重试。终止条件为任一事件丢失、重复入账或正常保存回归。

原代码复现失败，磁盘事件 ID 从 uncertain 被排队的 queued 覆盖。修复添加提交不确定状态，在尝试重命名之后失败时锁住本实例后续写入，包括此前已经排队的写入。重开后从实际磁盘校验并回放，同 ID 重试只保留一次。重命名前临时文件 sync 失败仍可显式重试，磁盘原文件和内存保持原值。

最小修复比引入新账本格式更容易验证，直接解决已复现的数据覆盖。本轮先处理这一缺陷，部分成交持久化继续由 #93 跟踪。研究账本和配置存储的同类阶段需要另行故障注入，当前用例仅覆盖模拟账本。真实断电、磁盘故障和长时容量保持未验证。

本地实际结果为 230 Node 全量通过，之后新增的重命名前失败恢复测试及全部 paper-ledger 用例通过。Vue 类型、主进程/预加载编译、Vite 构建、25 Python、静态官网检查通过。最终 PR 的 231 Node、UI/axe 与 Mac 结果以对应 Actions 为准。使用隔离合成数据，真实模型调用次数为零。
