# 2026-11-20 PositionScope 评审

基线为 main `beec34d`，包含 [#105](https://github.com/hash-panda/positionscope/pull/105)。开工时无开放 PR，开放 Issue 为 #3、#7、#23、#93。公开签名安装版仍是 [v0.2.10](https://github.com/hash-panda/positionscope/releases/tag/v0.2.10)，发布于 11 月 9 日，双架构签名、公证、装订、Gatekeeper 记录见 docs/releases/v0.2.10。本轮对 [主分支质量运行 44436932067](https://github.com/hash-panda/positionscope/actions/runs/44436932067) 的公开更新网络检查发起失败作业重跑，原失败记录保留。

复用 [#93](https://github.com/hash-panda/positionscope/issues/93)，推进部分成交的隔离重放实验。复用已有 consumeVisibleLiquidity，新增单标的、单方向的 JSON 输入协议，冻结委托数量、创建与到期时间，逐笔保留成交 ID、盘口 ID、源时间、成交数量、价格、名义金额与费用。输出包含 pending、partial、filled、expired 和剩余量。相同事件重试幂等，冲突事件拒绝；更新号或源时间回退的盘口不能继续消费。到期保留已成交部分，后续新盘口可以完成尚有效的剩余量。

固定合成案例中，两笔订单请求 1 和 1.5，深度为 2。第一笔全成，第二笔成交 1、剩余 0.5。JSON 序列化及重放得到相同结果；重复事件和相同盘口新事件不新增数量或费用；更新号递增的新盘口只完成剩余 0.5。另测卖侧、到期保留、身份冲突、时间回退、创建时刻不可成交、盘口数量步进和重复订单。输入保持不变。

该模块只由合成测试调用，尚未接入应用模拟账户。JSON 重放验证没有包含真实进程崩溃、磁盘原子提交、撤单、合约规则变化、最小成交名义金额、资金费、部分平仓或生产风险预算。这些属于后续集成验收，当前应用仍采用全成或不成。
