## 版本与交付约束

下一次新发布使用 **0.2.1**，以后只用纯数字 `x.y.z`（无 beta/rc/build 后缀，无多余前导零），Git tag 可为 `v0.2.1`。GitHub Release `prerelease=false`；这是发布渠道政策，不是对真实账户、盈利能力或全部使用场景已验证的承诺。

功能阶段不改 `package.json` 版本，保留已发布 beta.16 作为阶段基线；既有 Release 先查询并跳过，不重新签名或覆盖。只有最后发布 PR 在全部适用门槛通过后改成0.2.1及对应说明。不存在的新预发布版本必须拒绝，GitHub查询失败也不能当作“版本不存在”。旧公开产物和证据保留，不做旧预览版配置兼容或迁移。

## 质量门槛

1. 数据与事实：合成边界用例覆盖单位/方向/空仓/缺字段、源时间与采集时间、完整快照、过期/限流/重试/中断；没有真实账单就不显示已核对成交、转账或费用。
2. AI：可复算事实与模型解释分离；结构错误、伪造证据引用、缺失模型ID、超预算/超时、旧证据缓存必须有确定结果。真实模型质量、费用与时延只在有授权和实际记录时计验收；本轮自动开发不发送真实持仓测试。
3. 交互：480×600速览、工作台可调整尺寸、列表与证据保持选择、键盘焦点、浅/暗主题、数值色反转、隐藏金额、reduced-motion、无凭证/空仓/错误/过期/暂停/恢复；CI浏览器回归不能代替Mac多屏和系统菜单栏。
4. 隐私：独立应用身份及加密存储保持；原始响应/私有持仓/Key不能进入公开日志或遥测；更新检查不附带账户配置；通知权限由明确用户操作触发。
5. 发布：PR确切head检查与独立审查后合并默认分支；使用既有Mac签名链路、证书和Secrets，不降级未签名。只有最终发布PR改版本，官网在实际发布和资产核对之后同步。

最低证据包括相关类型/逻辑/构建和现有CI；需要界面变化时新增有意义的UI回归。新增数据引擎测试不接真实交易所账户，不为测提醒下单或转账。遇到不适用检查，应写明范围与原因，不填虚假通过。

## 研究结果与盈利验证

产品支持研究判断，目标是提高发现、复核与纪律执行的质量；不能把这一目标写成保证盈利。初期规则信号和AI观察以“偏多观察 / 偏空观察 / 暂不行动”配证据、反证、失效条件，不呈现未经校准的胜率。

真实账户持仓对照、签名包钥匙串弹窗、用户Mac原生场景、真实模型质量均仍未知。未来前瞻复盘需要在当时锁定规则/证据/候选，再收集足够后续样本，包含失败和未触发样本、基准、手续费/资金费/滑点、最大回撤与缺失期。尚未积累的历史、留存、收入和前瞻收益一律未知；不回填未来样本，不以AI炒股成功故事或现有持仓盈利证明系统安全有效。

## 失败、阻塞与范围

主线只支持 Binance，只读账户/公开行情；其他交易所扩展另排期。不为完成界面补出不存在的盘口、长期历史、基本面/解锁或资产身份映射。数据或模型不可用时保留可追溯缺口，状态不能显示成功。

新设计已获实施授权，但资金权限、真实账户测试和外部宣发授权边界不扩大。Search Console/Bing属性、品牌渠道及商业数据缺口仍在既有Issue记录；源码或网站上线不表示有访问、激活、留存或营收。当前计划不新增外部付费、发帖、群发或账号读取。
