# Binance 风格 UI 改造与验证

## 范围

基于 `master` 的 `bf43ee0bfb3731e6401070bd1d42e0ca8f106f3f`，按已确认方案重做持仓概览、多交易所资产、排序、通知、AI 分析、7 组设置和确认对话框。设计规则见仓库根目录 `DESIGN.md`。

保留 Vue 3、TypeScript、Electron 和已有图标库。设置详情拆为独立页面组件，通用密码输入框、开关与确认框复用。数据读取、保存和异常状态集中在 `useTradingApp`。

## 可重复检查

```sh
pnpm install
pnpm typecheck
pnpm test
pnpm build
pnpm exec playwright install chromium
pnpm test:ui
```

也可使用相应的 `npm run` 命令。`vue-tsc` 更新至与锁文件中 TypeScript 兼容的 2.2 系列；Playwright 和 axe-core 仅为开发依赖，不进入产品页面。

UI 脚本自动在空闲本地端口启动 Vite，通过 `addInitScript` 注入模拟 Electron API。它不会读取生产设置文件，不会发起交易所或 AI 网络请求，不会使用真实 API Key。截图写入已忽略的 `test-results/ui/`。

Linux 无中文字体时，建议安装 Noto CJK；也可将 `UI_TEST_FONT_DIR` 指向 `@fontsource/noto-sans-sc` 的目录，仅供测试注入字体。容器中的已有 Chromium 可通过 `UI_BROWSER_EXECUTABLE` 指定。这些选项不影响生产字体与启动方式。

## 与界面承诺相关的行为修正

- 使用交易所、原始交易对和多空方向构成持仓标识；主进程与列表共享排序函数，读取旧 symbol-only 记录时仍保留所有持仓。
- 主进程与设置预览共用菜单栏数字格式；隐藏金额同时作用于菜单栏。
- “重新分析”明确要求新分析，避免旧缓存结果被当作本次新结果。
- 交易所与 AI 凭证明确保存；检查 IPC 的 `success`，失败不会变为成功状态。
- 公开钱包地址是 Hyperliquid 只读路径所需的输入，不要求无用途的私钥字段。
- 恢复默认保留所有交易所与 AI 凭证；代理单独存取，清空代理会实际清除已配置客户端的代理。
- preload 事件订阅返回清理函数，页面卸载时清理定时器和监听。

## 实际运行边界

自动界面检查运行在 Linux Chromium，模拟账户及 IPC；它证明页面布局与这些交互的行为，不代替 macOS 原生应用验证。

仍需在 Mac 上确认菜单栏文字、窗口定位与失焦收起、系统开机启动、系统透明度以及真实只读 API 的连通性。此改造没有生成、签名或发布 DMG，也没有连接任何真实账户。

交易所账户字段的上游计算继续沿用原有适配器；本次不对资产口径作金融审计。AI 的可用性仍取决于用户的提供商 Key、模型与网络配置。
